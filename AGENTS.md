- **On-Board SPI Flash**: Macronix 128Mb SPI Flash (`MX25L12872F` / `mx25l12872f-spi-x1_x2_x4`)

## SC7F0 N1 HDMI2 V11: Standalone eMMC Boot vs. PCIe Reset

**Primary hardware source:** `/home/zzlee/llm-wiki/raw/SC7F0_N1_HDMI2_V11/SC7F0 N1 HDMI2 V11.pdf`, YUAN Hightech schematic, title `SC7F0 N1 HDMI2 V11`, Rev 1, dated 2024-01-23 (PDF created 2024-02-26). Use **V11**, not V10/V20, for this board. Verified directly against schematic sheets 10, 11, and 36; the A11→K11 and R8/R7 assignments agree with `constraints/zu4ev_pcie_pinout.xdc`. Wiki summaries are only pointers, not substitutes for the schematic. Component population and actual voltage on a particular board still require inspection/measurement.

- **PCIe PERST# with no slot host (sheet 36):** PCIe edge connector A11 is `RSTn_PCIe`, pulled up to `+E3.3V_X0` by **SR121 5.1 kΩ** on the schematic. `RSTn_PCIe` enters SU10 (`74LVC1G08GV`, AND gate) together with `X0_PS_PORb`; its output `X0_RSTn_PCIe` reaches FPGA **K11** through **SR59 33 Ω** (sheet 11). Thus the drawing does **not** show an inherently floating PERST# input on an externally powered board with `+E3.3V_X0` present. Confirm SR121 is fitted and the rail is up on the actual assembly if reset behavior is in doubt. `SR112 NC(0 Ω)` is shown as an unpopulated optional bypass around SU10; do not assume it is fitted.
- **PCIe reference clock (sheet 36):** slot A13/A14 (`REFCLKIN_P/N`) feed U14 (`SI53102-A3-GMR`) and the `X0_PCIe_CLKp/n` nets, then FPGA R8/R7 (sheet 11). Without a host supplying slot REFCLK, do not assume the PCIe core can link or its user clock can run. The drawing notes that U14 usage/population should be confirmed with procurement; check the assembled board before asserting its exact installed clock path.
- **PS independence (sheets 10 and 36; `rtl/zu4ev_pcie_card_top.v`):** PS POR (`X0_PS_PORb`) is generated by on-board reset circuitry and also *feeds* the PCIe reset AND gate; the host PERST# does not drive PS POR. The PS-generated `pl_clk0`/`pl_resetn0` and 100 MHz BAR0 CSR path must work without PCIe. By contrast, `pcie_user_rst_n = pcie_user_lnk_up && ~pcie_user_reset`, so PCIe-clocked/video paths and the 300 MHz reset tied to that signal remain held in reset without a link. Do not use standalone eMMC boot to claim those paths have been tested.
- **Observed 0807/1201 diagnostics:** with no PCIe host, 0807 ILA captured a PS read at `0xA0000000`: ARVALID=1, ARREADY=0, `sys_100m_rst_n`=0. `proc_sys_reset_0.xci` has `C_AUX_RESET_HIGH=1`, but RTL tied `aux_reset_in` HIGH, independently holding the 100 MHz domain in reset. The 26101201 fix ties unused auxiliary resets LOW; its ILA confirms the reset released and a PL-side read returned `0x12ABE380`, but **Linux `devmem` still wedged**. PS HPM0 is AXI4, while the RTL ties `RID=0` and `RLAST=1` into an AXI-Lite register path; investigate ARID/ARLEN (26101202 ILA), and never equate PL-side R handshake with completion at the CPU. Do not attribute the observed hang to a supposedly floating PERST#.

Always use the automated script **`./scripts/flash_a50t.sh`** to flash the SPI Flash memory:

```bash
./scripts/flash_a50t.sh
```

**What `flash_a50t.sh` does automatically:**
1. Invokes Vivado batch TCL script [`scripts/program_flash_a50t.tcl`](file:///home/zzlee/qpcie/scripts/program_flash_a50t.tcl).

## 📐 RTL Architectural Design Guidelines

1. **BAR0 vs BAR1 Hardware Demuxing**:
   - Use `m_axis_rx_tuser[9:2]` One-Hot BAR Hit indicators from 7-Series PCIe core (`pg054`).
   - `m_axis_rx_tuser[2]` = BAR0 Hit (DMA Registers `axil_reg_space.v`).
   - `m_axis_rx_tuser[3]` = BAR1 Hit (User IP Cores / EDID / TPG).

2. **4-DW MWr (64-bit Address Memory Write) Handling**:
   - On 64-bit hosts (e.g., Jetson Orin NX), `iowrite32` generates 4-DW MWr TLPs.
   - Beat 0 contains 64-bit Address (`AddrHigh`, `AddrLow`).
   - Beat 1 contains the 32-bit Write Payload Data in `m_axis_rx_tdata[31:0]`.
   - `pcie_7x_axi_bridge.v` buffers Beat 0 address and packs Beat 1 payload into `cq_tdata[127:96]`.

3. **CQ RX Decoder State Machine**:
   - `cq_rx_decoder.v` must transition back to `IDLE` state as soon as AXI `rvalid` or `bvalid` is asserted, resetting `s_axis_cq_tready = 1` for continuous, back-to-back MMIO requests.

## 🏷️ Vivado Design Modification Rules & Hardware Versioning (`C_VERSION`)

> [!IMPORTANT]
> **Mandatory Rule for any Vivado Modification**:
> Whenever Vivado Block Design (BD), RTL, or IP configurations are modified, **ALWAYS verify and increment/update the `C_VERSION` parameter before regenerating targets and re-exporting the XSA / bitstream.**

1. **`C_VERSION` Format Specification (`0xYYMMDDpp`)**:
   - Format: `32'hYYMMDDpp`
   - `YY`: 2-digit Year (e.g., `26` for 2026).
   - `MM`: 2-digit Month (e.g., `09` for September).
   - `DD`: 2-digit Day (e.g., `30` for 30th).
   - `pp`: 2-digit Patch / revision count for that date (e.g., `01`, `02`, `03`...).
   - Example: `32'h26093001`

2. **Standard Parameters (`zzlab_env.v` / `zzlab_env_0`)**:
   - `C_VERSION`: Current date + patch number (`32'hYYMMDDpp`).
   - `C_PLATFORM`: `"PCIE"`.
   - `C_BOARD_VERSION`: Maintain target board hardware revision (e.g., `32'h00000101`).

3. **Mandatory Post-Modification Workflow**:
   1. Check & bump `C_VERSION` in `zzlab_env.v` (or corresponding top/wrapper).
   2. Reset and regenerate BD targets (`reset_target all`, `generate_target all`).
   3. Export updated XSA (`write_hw_platform -fixed -force <path>.xsa`).
   4. Update PetaLinux hardware description (`petalinux-config --get-hw-description=<xsa> --silentconfig`).
   5. Recompile PetaLinux images / repackage `BOOT.BIN` and update release artifacts.
