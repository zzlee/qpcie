# Phase 1 / Todo 1.5 — matched 0x26102902 PS image, r2 release, single-COMMIT deployment, first-boot failure and the corrected r3

Date: 2026-10-29/30. Card: `rd@sc7f0-test.local` (`0000:03:00.0`), host boot ID
`c7915db6-0a6d-4917-93bc-7e8045d54270` (never changed; the host was never rebooted).

Headline: **the matched PS image was built, injected, packaged, audited offline, and
flashed with exactly one COMMIT — the card's active hardware version is now
`0x26102902`. The PS does not reach userspace on that image.** The cause is
isolated to one auto-generated bootarg, a permanent gate for it now exists, and a
corrected release (r3) is built and offline-verified, ready for a flash decision.

---

## 2. r2 offline audit — 35/35 PASS before flashing

`build/verify-vcu-r2-release.sh` → `RESULT: VCU_R2_RELEASE_VERIFY_PASS`, 35 PASS / 0 FAIL
(`build/sc7f0-capture-26102902-r2/logs/final-verify.log`), including: frozen R7/r1 trees
untouched; r1 still `NOT_DEPLOYABLE`; BOOT.BIN payload re-render proves it carries this
release's bit; capture-image audit PASS at `0x26102902` and correctly FAIL at
`0x26102901`; strict-ustar 4-member upgrade tar; tamper probe refused; deploy-tool
preflight PASS on r2 and still refusing r1.

`NOT_DEPLOYABLE` was removed for r2 because the gate that forced it (PS image built
from a *different* XSA) is gone: `PS_IMAGE_MATCH.json` reports
`deployable: true`, `ps_image_pl_base_version: 0x26102902`,
`imported_xsa_sha256 == packaged fpga/hardware.xsa`.

One staging correction is recorded in
`build/sc7f0-vcu-ps-26102902-20261029/logs/r2-regeneration-record.txt`: the first r2
tree (21:47) froze `SOURCE.sha256` before a fix to `scripts/accept_sc7f0_vcu_board.sh`,
so the deploy tool's own SOURCE gate refused it (observed, fail-closed). r2 was
regenerated at 21:58 with byte-identical `images/` and tar.

## 4. Active Hardware Version verification — achieved

Read-only, host side, after the failed recovery wait
(`logs/board-readback-after-deploy.txt`, `logs/board-version-after-deploy.txt`):

```
qpcie_upgrade --status
  Hardware Version  : 0x26102902 (Date: 2026-10-29 Rev 02)      <-- was 0x26102901
  Hardware Magic    : 0x12ABE380 [VALID]
  Upgrade Status    : 0x00 (IDLE / Ready)
  Board PS DDR4 Buf : 0x0000000000000000                        <-- was 0x3303D000
host dmesg: one clean re-probe at [105968] (video0 + ALSA card 0 + H2C + debug mailbox),
            no repeat link drop since
```

So the new bitstream **is** the one loaded, PCIe/PL/upgrade-engine are healthy, and the
version register moved. The zeroed PS DDR-buffer register plus the dead mailbox say the
PS-side software is not publishing anything: PL is up, PS userspace is not.

## 5. HDMI 4K60 capture verification — not possible on this image

`scripts/accept_sc7f0_vcu_board.sh` and `scripts/sc7f0_ps_capture_4k60.sh` are written,
offline-tested against the live board (upload path reworked to `printf %b` chunks
because the PS has no `base64`/`xxd`; byte-exact round trip verified), and they are
read-only by construction. They cannot run: every probe goes through the PS debug
mailbox, which is down. Host-side read-only datapoint:

```
v4l2-ctl -d /dev/video0 --query-dv-timings  ->  VIDIOC_QUERY_DV_TIMINGS: failed: No data available (all zeros)
```

The RX front-end is configured by the PS `qpcie-hdmi-daemon`; with no PS userspace there
is no 4K60 timing to capture. No capture test was attempted against a card in this state.

## 6. Why the PS does not boot userspace — one regenerated bootarg

Offline decode of the two packaged `image.ub` FITs (`build/dt-inspect.py`, dumps in
`build/sc7f0-vcu-ps-26102902-20261029/dt/`, diff in `build/dt-r7-vs-vcu.txt`):

| FIT component | R7 `sc7f0-capture-26102901-r1` (boots) | r2 `…-26102902-r2` (no userspace) |
| --- | --- | --- |
| kernel `Image.gz` | `5c2066f8c2199e02…` | **byte-identical** |
| initrd rootfs | 31,113,538 B | same 2585 files; only the four injected daemons + marker differ |
| DTB | `187982ef…` | `fe6839b9…` |
| `BOOT.BIN` | `87f337f9…` | `872d97a7…` |

Every DTB difference but two is phandle renumbering. The functional pair is:

1. **`/chosen:bootargs` grew `cma=1000M`**
   (`earlycon console=ttyPS0,115200 clk_ignore_unused root=/dev/ram0 rw cma=1000M`),
   regenerated into `CONFIG_SUBSYSTEM_BOOTARGS_GENERATED` by the VCU hardware import
   (`project-spec/configs/gen-machineconf.log:128`). This card's low DDR bank is
   `0x0-0x7ff00000` and already carries `dau_fpga@30000000` 256 MB `no-map`,
   `cma,video@40000000` 256 MB, `cma,qdmabuf@50000000` 64 MB and `cma,vcu@54000000`
   672 MB — ~1.25 GB pinned before Linux starts, with the `root=/dev/ram0` initrd in the
   same bank. A second, *global* 1 GB CMA does not fit under that.
2. `vcu@80080000` + `al5e@80080000` appear (intended), no IRQ/ reservation change.

The only other candidate is the rebuilt `BOOT.BIN`, and its FSBL `psu_init` is now proven
register-for-register identical to the accepted XSA — so the memory-layout change is the
single thing that differs in behaviour, and it is exactly the class of change that kills
early userspace while leaving PL/PCIe untouched.

## 7. The fix, and a corrected release (r3) — offline-verified, not flashed

* `petalinux/.../device-tree/files/sc7f0-memory-layout.dtsi` — `/delete-property/ bootargs;`
  then the card-validated bootargs, included **last** from `system-user.dtsi`; added to
  `device-tree.bbappend`. This is the load-bearing fix: `petalinux-build` *does* put
  `cma=1000M` back into `configs/config` after any import-time pin (proved twice), but the
  pinned `chosen` node wins in the built DTB.
* `scripts/check_sc7f0_memory_layout.py` (+ `scripts/sc7f0_fdt.py`, pure-python FDT so no
  `dtc` needed): gate on `/chosen` bootargs, every `/memory` reg, and the whole
  `/reserved-memory` map, against the card-validated baseline.
  Non-vacuity is built in: the same gate still **refuses r2's own image**.
* `scripts/check_sc7f0_ps_build_integrity.py`: separates the one auto-generated config
  line from real source drift (the blanket `sha256sum -c PS_BUILD_INPUTS.sha256` used by
  `check_sc7f0_capture_image.py` fails on every good build now); legacy builds keep the
  original blanket behaviour.
* FSBL evidence gate corrected: the r2 audit read
  `project-spec/hw-description/psu_init.c`, which PetaLinux 2023.2 no longer regenerates
  (a leftover). r3 reads the platform copy the build recorded — `fsbl-psu_init.sha256` —
  and compares the full `(offset, mask, value)` set. r2's *conclusion* stands (identical
  register program); only its evidence path was wrong, and that path is now closed.
* `build/{assemble,finalize,verify}-vcu-r3-release.sh`, `build/ps-matching-vcu.20261029-222700`:

| item | value |
| --- | --- |

| FSBL psu_init | `7fe2c51a…`, 826 register writes identical, `pl_clk1 ≈ 33.333 MHz` |
| `images/image.ub` | `61150557a089b2b73820a803a09889b6eeb800e4b922ff08e67e257ea815a52e` (r2: `f22ff9a7…`; delta = the DTB bootargs pin) |

## 8. Recovery position — an operator decision, deliberately not taken unilaterally

The card is not bricked: PL, PCIe, version register and the H2C engine (`IDLE / Ready`)
respond, and the rollback material exists twice over — the frozen
`build/sc7f0-capture-26102901-r1/images/*` (SHA-pinned) and on-card
`/run/media/BOOT-mmcblk0p1/.backup_cli_20261029T140050Z/` (currently unreadable,
reading it needs PS userspace).

* `scripts/deploy_sc7f0_capture_vcu.sh` **cannot** deploy again in this state as written:
  its eMMC-backup and readbacks go through the PS mailbox, so it aborts before any COMMIT
  (fail-closed by design). r2 is additionally locked by its own `deployment/commit-issued`.
* A host-side-only path (`qpcie_upgrade --package` → one `--commit` → `--reboot`) does not
  need PS userspace, but it skips the tool's backup gate. That is a deviation from the
  designed protocol and is the operator's call, not mine by default.
* Nothing has been retried or improvised: one COMMIT, no second reboot, no module reload,
  no host reboot, no JTAG/MCU action.

3. r2's FSBL/VCU-clock gate read a stale `project-spec/hw-description/psu_init.c`
   leftover; the gate now reads the FSBL platform copy the build recorded. r2's own
