# R6 full C2H/capture profile review — scoped, not warning-free

Candidate: `26102804`, `build/dual-video-26102804-r6`. The original debug-profile rejection and `build.exit=1` remain unchanged. A separate full-profile acceptance must pass `check_sc7f0_full_profile.py`, retain its inputs/tools/tests, then export a matching XSA. Neither R5 nor any counterfactual R4 bit is accepted by this review. This is capture-baseline hardware signoff, not VCU, Linux runtime, package or card acceptance.

## Reset, admission and ownership

`export_sc7f0_full_evidence.tcl` opens the actual routed DCP read-only. Its output binds the checkpoint path/SHA and checks 25 explicit four-FDPE release chains: common clock/preset, ASYNC_REG, VCC CE, GND first D, and direct preceding-Q-to-D. `sc7f0_reset_proof.py` exhaustively proves each extracted LUT cone is the OR of explicitly named reset requests with declared polarities (276 truth cases). Data-dependent resets, unknown primitives, extra roots and changed release chains fail closed. Request levels originate from reset controllers, PCIe reset/link state, synchronized software reset controls and capture reset GPIOs; release waits four destination edges. Overlap/deassertion glitches cannot bypass those four release stages. This does not claim measured electrical pulse widths or authorize arbitrary asynchronous reset sources.

Reset/filler is not a retirement mechanism. Raw engine reset contracts are unchanged. Capture GPIO resets are owned by the official CSC/framebuffer drivers and may follow graph/DMA teardown only after the tap fence. The patched VIPP waits before graph stop, terminate and VB2 buffer return, including startup unwind. A permanently stalled transaction/IRQ/clock may block close indefinitely; no forced reset, fake POP or feeder thread is permitted.

The R6 ABI1.1 fence is carried in the same ordered command FIFO as ENABLE/disable. Memory-domain ACK advances one token at a time only after disable, an empty command boundary, no tap output activity and `started_count == retired_m`. Admission that increments `started_count` is in that same memory domain and requires `enable && credits && !credit_clear`. RX-side late headers after disable are discarded without starting DMA; synchronizing enable/busy separately is not used as stop proof. Retirement comes from actual framebuffer completion and metadata POP, not tap EOF.

Actual vendor CSC/framebuffer simulation now asserts that IRQ cannot precede all outstanding AXI write responses; B responses are deliberately delayed 11 cycles. This validates the callback-to-retirement dependency for the configured NV12 writer. Actual-XPM tests cover stopped memory clock/stale idle, same-cycle admission, pending retirement, combined stops, full command FIFO and refused-write token accounting. Simulation inputs are hashed before execution and checked afterwards. The kernel waits for a fresh matching token, rejects the old ABI and retains one pending token across timeouts: retries cannot run the sequence around a permanent fault. A new ENABLE/format/prepare is refused while that fence is pending.

## Exact CDC inventory (5,116 paths)

* 32 reset-entry Critical rows: the above 25 concrete chains and assertion-cone proof.
* 7 diagnostic Critical rows: three FDRE/ASYNC_REG stages each; complete final fanout is only CSR readback bits 25..31. These are approximate level diagnostics, not coherent event counters, flow control, frame admission, reset/credit or health progress proof.
* 3,664 CDC-15 FIFO data rows: ten explicit XPM FIFO roots, exact RAM clock-to-FWFT-output-register shapes. The reviewed wrappers use full/empty and reset-busy ownership guards; header/metadata credits and packet complete-payload reservation prevent consuming unwritten slots. No active-transaction reset is used to drop a frame. Width82 config includes the stop token; queue/SG depths were not reduced.
* 448 probe meter rows: seven exact 32-bit held snapshots, only frequency/raw-cycle readback; request/ack protocol holds the source snapshot, with the existing 10ns datapath bound. Not a generic multibit crossing exception.
* 180 frozen GT Wizard1.7.17 calibration rows: exact source/clock/destination matches plus pinned XCI component configuration. The vendor counter synchronizes its run control, enters HOLD for 16 reference cycles, then updates the result. Missing/changing clocks may fail calibration; this is not a guarantee of coherent instantaneous frequency during clock loss.
* 4 frozen VPHY CDC-6 rows: three frequency buses and DRU controls. Vendor `clkdet.sv` stops counting, waits 255 reference cycles, then asserts capture-valid; consumers do not use the changing raw count as a live bus. DRU bits are independently synchronized reset/control levels under the vendor initialization protocol. Clock-loss transitions are not a new frame/timebase guarantee.
* 416 frozen HDMI RX CDC-26 rows: exact clock/path identities and unchanged pinned HDMI IP parameters; vendor FIFO memory advisory, not a blanket exclusion of all HDMI descendants. Normal FIFO ownership remains required.
* Remaining CDC-6: independent sticky diagnostics; two independent approximate enable/busy status bits (explicitly NOT teardown proof); two registered Gray64 timestamp samplers with four stages and separately checked 128 direct bit paths, 6ns delay and skew bounds before optimization and after route.
* 361 vendor recognized single-bit/Gray synchronizer Info rows. Unknown rules, malformed severities, missing detail, changed multiplicity or unclassified paths fail.

Pinned baseline CDC SHA: `babc386d724c54804b9f4362c7be27f5a11185a09f75545bcea360b3f5ac4827`. PHY/RX XCI hashes are pinned to the verified 26102702 input manifest; component parameters must be identical. Identity is supporting evidence, not the approval reason by itself.

## I/O, clocks and methodology

The seven HIGH input-delay and six HIGH output-delay entries must be exactly the reviewed asynchronous DDC/HPD/5V/refclk-ready signals, status LEDs and forwarded TX PHY clock. These are not source-synchronous pixel data. Physical pin, direction and I/O standard are checked against the V11 implementation. No arbitrary zero input/output delay is added to hide them. All internal unconstrained/no-clock/multiple-clock/loop/partial-delay checks must be zero. Routed setup, hold, pulse width and all skew checks must pass.

The full profile requires exact methodology IDs, severities and counts: DPIR-2=192, LUTAR-1=35, TIMING-9=1, TIMING-18=12, ULMTCS-1=1, CLKC-11/40/56=2 each. DPIR/LUTAR are the reviewed synchronizer/reset structures; TIMING-9 depends on complete CDC proof, TIMING-18 on the exact external-interface role list. High-fanout control-set and shared vendor PHY MMCM advisories are retained, not converted into zero-warning claims. The shared RX/TX PHY/refclock infrastructure remains; removing those clocks or asserting arbitrary clock groups is not approved.

## DRC and licensing

Exact R6 DRC inventory: DPIP-2=74, DPOP-3=13, DPOP-4=30, REQP-1935=2, RTSTAT-10=1, all Warning. The first three are existing address/CSC/DRU DSP pipelining recommendations; positive routed STA and functional tests apply, not a mandatory extra latency change. The two NO_CHANGE BRAMs are specifically audio channel0's synchronous decoupling FIFO, with `wr_en && !full` / `rd_en && !empty`; normal FIFO operation avoids unread-address collisions. The one no-routable-load net is vendor HDMI RX `SYS_INST/lclk_cke[3]`, an unused clock-enable lane, not unconnected capture data. All detailed findings/cells are hash-pinned; even an equal-count warning at another FIFO fails. HDMI subsystem and its nested RX core must both report Purchased, not evaluation/design-linking.

## Negative tests and limits

Real-candidate private-copy mutations reject negative setup/hold, new HIGH I/O, unknown multibit CDC, unsupported CDC severity, missing Gray hooks, empty source manifests, changed methodology, mismatched DCP binding, same-count DRC at another memory, non-purchased HDMI and present TX hardware. Extracted-netlist mutations reject XOR/wrong-polarity/data-dependent assertion cones, missing stages, nonconstant CE/D, nondirect release, changed physical pins and probe control fanout. Native actual-driver tests cover stale ACK, unavailable commands, readback failure, wrap, repeated timeout reuse and pending-stop/new-start exclusion. ARM64 objects compile with -Werror without changing the prepared kernel config/symbols; this is not a full-image or real-kernel result.

Capture `dropped_frames` is source-side FIFO/admission-rejection telemetry, not a universal count of every uncredited/disabled input frame. Source SOF sequence gaps are retained and must be used for end-to-end drop accounting. SOF time remains the sampled source timebase, not dequeue/IRQ time. DMA-BUF export does not establish VCU import. No encoder/daemon, zero-copy, audible lip-sync or whole-card runtime acceptance is claimed here.
