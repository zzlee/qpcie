## Reset-chain evidence and PS teardown safety follow-up

- R5 is still rejected; no new XSA, image/package, flash or whole-card build is running.
- The 32 Critical reset-entry rows map to25 unique synchronizers. Actual routed-netlist inspection checked all100 FDPE stages: ASYNC_REG enabled, identical clock/preset across each chain, CE tied high, first D tied low, and direct previous-Q→next-D release connections. Assertion LUT INITs and every source startpoint are recorded. This is structural evidence, not approval of request pulse/glitch semantics or FIFO ownership.
- Evidence: `build/.r5-reset-cones-latest` → `reset-cones.rpt`; inspection script `scripts/inspect_sc7f0_reset_cdc.tcl`. Initial checker attempt rejected Vivado's boolean ASYNC_REG value1 because it expected literalTRUE; failure preserved, checker now parses strict Tcl booleans.
- Found and fixed a PS teardown hazard: vendor VIPP graph stream-off discards subdevice stop errors, and the old patch then unconditionally terminated/reset DMA and returned buffers after a tap-drain timeout. VB2 itself also forces return of ACTIVE buffers after stop_streaming returns, so merely returning early would not preserve memory ownership.
- New `sc7f0_tap_quiesce()` runs before graph shutdown/DMA terminate in STREAMOFF, and before terminate/buffer return on start-error unwind. It retries failed drains with sleep/rate-limited logging and does not return until TAP reports disabled/no owned frame and any posted ENABLE has been observed. Added a start_unconfirmed latch: if a memory clock stops before applying ENABLE, a stale idle CSR snapshot cannot falsely authorize teardown. If ENABLE/disable were never observable, this conservatively stays fail-stopped rather than guessing that queued commands disappeared. No reset or fabricated metadata POP is used to fake success. NULL-tap legacy behavior is unchanged.
- Explicit failure-policy limit: a permanently stuck DMA/IRQ can leave STREAMOFF/close blocked indefinitely, keeping teardown from releasing ownership. This is fail-stop, NOT bounded shutdown or proven automatic recovery; kernel-device close/removal/reset and complete writer/AXI idle behavior still need runtime review. Do not place the optional VCU daemon into the board-required watchdog set to mask it.
- Regenerated patch reapplies cleanly to the pinned Xilinx kernel. Both updated AArch64 kernel objects compile with -Werror; prepared kernel config/autoconf/Module.symvers hashes remain unchanged. Fourteen native tests pass, including actual quiesce-loop source under recoverable/permanent failure and unconfirmed-start models, patch application/order, CDC identity/completeness and Gray-hook negatives. No kernel/DMA runtime acceptance is claimed.
