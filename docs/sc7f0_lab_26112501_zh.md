## 軟硬體界面

PL 的 URAM 參考緩衝為 349 KiB；實際是否使用，須另看編碼器每幀的 L2 使用位元。PS 從 VIPP 接收硬體 SOF ID 及時間戳，以 12 個共享輸入緩衝及 8 個 OMX 輸出緩衝編碼。輸出 callback 先驗證 OMX 指標、範圍及長度，再複製至有上限的 scratch 進行 NAL 掃描；輸入仍只能在 EBD 後歸還。驅動以 epoch、credit、停止交握及最後寫入的 fence 管理回收；未確認完成時隔離 DMA 頁。四個 NM16 與九個壓縮 host buffer 為試驗條件。主機 KMS 模組仍嚴格核對 PL 版本，應針對測試主機的 kernel headers 重建；PS 程式與原生 OMX 控制不需要 LD_PRELOAD。

## 已有數據（非新套件驗收）

## 重現、復原與保存

```sh
# 開發機：F 是已核准的不可變 26112419 release-lab；B 必須不存在。
scripts/sc7f0_lab19_rootfs.sh "$F/fpga/hardware.xsa" "$B" 26112501
scripts/sc7f0_lab19_package.sh "$B" "$F"
scripts/sc7f0_flash.sh --build "$B/release" --host rd@sc7f0-test.local --yes
# 測試機：A 是含 RELEASE.sha256 與兩個 host source tar.gz 的目錄，BIN/OUT 須全新。
bash sc7f0_lab19_host_tools.sh "$A" "$BIN"
bash qualification/accept-package.sh "$OUT" "$MATRIX" "$BIN" "$R/candidate/packaged-runtime.sha256"
bash qualification/credit-reconnect.sh "$BIN" "$R/credit-reconnect-new"
```

Host 套件編譯需相符 kernel headers、libdrm 開發檔、pkg-config、gcc；測試需 v4l2-ctl、FFmpeg、Python。PS 須等待實際 HDMI lock 與兩服務啟動，第一次冷啟檢查太早；重試沒有更換執行檔。讀取 PS 管理 mailbox 後需確認無使用者與 plane 停用，再重綁**同一 build ID** 的 KMS 模組才進行視訊擷取。每個 PS 暫存目錄用 mktemp。部署使用 HEVC CBR、AVC 切換經 `/etc/default/sc7f0-vcud` 指定 codec、`RATE=cbr|vbr` 與 range=16 並重啟服務，host 同時設對應 FourCC、target 與 peak。包內 AVC 欄位預設 8 不是經選定的 AVC profile。最終 host 已設回 HEVC CBR 40/40、ACK 42/42、HDMI locked、wireplumber active。

回復來源為 `rgb-vcu-uram-26112419/release-lab/` 的原始已驗證包及相符主機模組；需在維護時段另走同一 VERIFY/COMMIT/boot ID/讀回流程。`~/sc7f0/tmp/upgrade.kYM0DsjE/module-before.ko` 是本次主機驅動的回復副本。本輪未再次燒錄回復，舊 `/run/` 臨時服務不屬於舊 rootfs，回復升級包本身不會還原這些實驗檔案。
