CASE FILE · 08-21

辦案實錄：pg054 byte order

🔍

症狀

128-bit TLP 資料全面錯位，原因不明。

📑

agent 的辦案手法

交叉比對 pg054 官方文件的位元組順序定義 ↔ RTL 介面假設，定位出兩邊不一致——『文件對程式碼』的苦工，agent 不會累。

🔁

過程：47 個 commits 的迴圈

08-21 當天多輪修正：每輪先過 testbench，關鍵輪上機驗，最後以實機 SG DMA + capture 通過結案。

⚖️

紀律：兩道門

agent 的輸出只是『候選答案』——testbench 與實機是兩道門，沒證據不結案。這才是可信任的原因。

PITFALLS

踩過的坑

🔴

pg054 byte order 高

7-Series PCIe IP byte order 與自訂介面不一致，128-bit TLP 資料錯位，08-21 修正。

🔴

4-DW MWr（64-bit 位址）高

iowrite32 產生 4-DW MWr：beat0 是 64-bit 位址、beat1 才是 payload，需在 CQ 側 buffering 後打包進 cq_tdata[127:96]。

🟡

CplD Tag / Requester ID 中

Completion 回覆需依 desc-fetch / H2C / C2H FIFO 正確路由。

🟡

128-bit TLP 資料對齊 中

資料路徑對齊 + TLP 長度處理需配合 SG descriptor。

🟢

ARM64 cache ordering / SMMU 低

USERPTR/DMABUF 時處理 cache coherency；retained head SMMU fault 待 Phase2 驗證。
